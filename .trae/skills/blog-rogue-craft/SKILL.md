# Blog Rogue Craft（博客邪修大法 · 纯 AI 零人工版）

> 一套**纯 AI、零人工**的博客设计与开发工作流：新手友好，无需在 Figma / Google AI Studio / Google Stitch 与 IDE 之间反复对齐。从原型图到代码落地，从风格定义到持续优化，全部交给 AI。

**文章出处**：[《纯AI，零人工》](https://tblog.mmzhiku.xyz/posts/ai/ai-blog-ai-zero-editing/) —— 本文是该方法论的完整复刻与可执行版。

---

## 0. 速记卡（5 阶段工作流）

```
[需求] → [AI 定整体风格] → [编写原型图 .html，还原度>截图] → [生成 design.md 代码规范]
                                                                          ↓
        [持续优化 ← 动效 / 资源 / 懒加载 / 定期扫描]                      ↓
                          ↑                                              ↓
                  [TDD 红绿测试 + 顶模审查]  ←  [按代码规范开发，头脑风暴生成 PLAN]
```

---

## 1. 正确流程（CRITICAL：必须严格遵守顺序）

| #   | 阶段                     | 核心交付                             | 关键原则                         |
| --- | ------------------------ | ------------------------------------ | -------------------------------- |
| 1   | **先说结论**             | 一句话需求                           | 别绕弯，先给目标                 |
| 2   | **AI 定整体风格**        | 风格分析（配色/字体/间距/组件/布局） | 整体先于细节                     |
| 3   | **编写原型图 `.html`**   | 纯 HTML+CSS 原型                     | **还原度比截图更高**             |
| 4   | **AI 生成代码规范**      | `design.md`                          | 把风格固化为可复用的设计令牌     |
| 5   | **代码必须各种红绿测试** | 测试用例 + 视觉/交互验证             | TDD：先写测试/对比截图，再写实现 |
| 6   | **持续优化**             | 动效 + 资源 + 懒加载 + 定期扫描      | 优化是长期工程，不是收尾         |

> **红线**：跳过任何一个阶段都会导致"画面怎么黑了 / css 失效 / 需求被无视"等翻车。

## 2. 原型图（核心阶段 · 邪修大法）

> **我不是什么设计大师，也不按企业规范**。新手不用在 Figma / Google AI Studio / Google Stitch 和 IDE 之间反复对齐。
>
> **直接参考现成 UI 库、开源代码、参考网页中挑元素拼接**。

### 2.1 原型图步骤

1. **在 UI 库或开源代码中找参考**（按需求选）
2. **若只有代码或图片**，让 AI 生成对应 HTML 原型
3. **对比原型是否符合需求**（要求 95%+ 还原度）
4. **让 AI 按代码规范把原型接入指定页面位置**（**不是直接搬代码**）
5. **本地微调测试**；除 Codex 外通常需多轮

### 2.2 常见模块速查表

| 模块        | 子元素                     |
| ----------- | -------------------------- |
| **导航栏**  | logo、菜单、按钮           |
| **Hero**    | banner、首屏展示字体、引导 |
| **Content** | 图文、卡片、表格           |
| **Footer**  | 版权、联系信息             |

### 2.3 参考来源选择（按目标匹配）

| 你的状态     | 建议               |
| ------------ | ------------------ |
| 没灵感       | 刷网站库找审美参考 |
| 想挑现成组件 | 看组件库           |
| 明确结果     | 抄对标网站         |

### 2.4 推荐资源

- **提示词优化**：[PromptPilot](https://promptpilot.ai/)
- **网站参考**：[awwwards](https://www.awwwards.com/)、[OnePageLove](https://onepagelove.com/)、[mobbin](https://mobbin.com/)
- **UI 组件库**：[Uiverse](https://uiverse.io/)、[React Bits](http://reactbits.dev/)、[CodePen](https://codepen.io/)、[Magic UI](https://magicui.design/)、[Aceternity UI](https://ui.aceternity.com/)
- **图标库**：[Iconify](https://iconify.design/)（推荐）

### 2.5 提示词模板 · 从原型生成代码规范

```
我需要当前业务的整体UI设计做一次风格迭代，我会给你几张参考设计的截图
请你仔细分析它的视觉风格，然后把这种风格应用到我的当前页面上
请重点还原这几个方面：
1. 配色：主色、辅助色、字体颜色、背景颜色
2. 字体：标题和正文的字号层级、粗细、间距、对齐方式、行高
3. 间距与留白：模块之间的间距、元素之间的呼吸感
4. 组件样式：按钮、卡片、导航栏的圆角、阴影、边框
5. 整体布局：参考它的排版结构来组织页面
```

### 2.6 提示词模板 · 生成 design.md

```
请把我们这套设计风格保留下来，总结成一份设计规范文档，保存到design.md文件中，内容包括
以后我每做一个新页面，你都要先读这份design.md
1. 配色：主色、辅助色、背景色、文字色的具体色值
2. 字体：标题和正文的字号、字重、行高
3. 间距：常用的内外边距和模块间距
4. 组件样式：按钮、卡片、导航栏的圆角、阴影、边框规则
严格按照里面的规范来设计，保证整个项目风格统一
```

> **执行纪律**：所有原型产物（HTML/设计规范）放入 `.trae/` 目录归档，不污染项目根。

## 3. 设置规范（接手新项目时 · 不建议直接 `/init`）

### 3.1 反模式（直接 `/init` 的 3 大风险）

1. **技术栈不熟悉** → 无法判断实现阻力，容易踩坑
2. **代码质量未知** → 若项目本身混乱，初始化会让问题更难处理
3. **来回纠错成本高** → 报错、样式失效、需求被忽略等问题会反复出现

> **用户原话痛点**（来自作者实战经验）：
>
> - "报错你没看到嘛"
> - "画面怎么黑了"
> - "不要无视我的需求"
> - "不用抱歉，帮我改对啊"
> - "怎么切换页面后css失效了啊"

### 3.2 正确流程

1. **让 AI 先深度分析项目结构**、开发注意事项和目录树
   - 输出**架构图、模块依赖、核心数据流**
2. **重点询问**：坑点、配置方式、调试方法、部署注意事项
   - 输出一份**「新人上手清单」**和**「常见翻车现场合集」**
3. **踩坑完成后**，再执行 `/init`
   - 让 AI 按企业级规范、解耦模块边界生成 `claude.md` 代码规范
4. **检查 `claude.md`**
   - 例如若其中提到提交代码规范，而你有对应 skill，**可改为让其使用指定 skill**
5. **再让 AI 做一次头脑风暴**，按企业级规范对齐内容，迭代一次
6. **TDD 是神**（写测试 → 写实现 → 重构）

## 4. 开发

### 4.1 步骤

1. **获取原型 HTML**（来自阶段 2）
2. **头脑风暴学习原型图**，明确需求并对齐，生成 **PLAN**
3. **按代码规范开发**
   - **非 Codex 场景**：需提醒使用 TDD 相关测试 skill，**避免白屏测试**
4. **检查交互**
   - 无卡顿、断层、闪烁
   - 确认节流、防抖、重排处理到位
   - 检查性能损耗和代码规范
5. **确认整体无问题后再提交**

### 4.2 设计原则（贯穿开发全流程）

- 保持博客风格统一：**文章页面专注阅读，相册首页专注视觉**
- 遵循「不受欢迎的博客技术特征」原则（参见 [纸鹿摸鱼处](https://tblog.mmzhiku.xyz/) 博客原则）
- AI 绘画作品**只在首页展示**，其他页面专注文章内容
- 各司其职，互不干扰

## 5. 优化（开发完成 ≠ 结束）

### 5.1 动效 · 高端设计师作品集 / 创意机构官网风格

想让页面更有质感，依次从上往下分层显示，使用以下提示词：

```
我想要更像高端设计师作品集/创意机构官网的动效，不要普通淡入。
首屏需要有完整 opening animation，标题要有强视觉进场，比如遮罩揭开、位移、压缩后归位。
滚动到每个模块时，英文大标题先大幅进场，卡片再依次 stagger 出现，
图片要有 reveal 或轻微 parallax。
整体动效要夸张一点但高级，节奏慢一些、缓动丝滑，不要廉价弹跳，也不要影响性能。
可以用 GSAP + ScrollTrigger。
```

**动效关键词速查**：

- 进场：opening animation、遮罩揭开、位移、压缩后归位
- 滚动：英文大标题大幅进场、卡片 stagger、图片 reveal / 轻微 parallax
- 缓动：夸张但高级、节奏慢、丝滑、不要廉价弹跳
- 技术栈：**GSAP + ScrollTrigger**

### 5.2 资源优化

| 资源       | 策略                                                                       |
| ---------- | -------------------------------------------------------------------------- |
| **图片**   | 压缩、调整分辨率适配位置、**转 webp**                                      |
| **文字**   | 压缩到**日常用字约 6000 字**，含**数字、字母、标点符号、ASCII 码**字体子集 |
| **懒加载** | 瀑布流图片、文章数等异步请求                                               |
| **请求**   | 合并小图标为 **SVG Sprite**，减少 HTTP 请求数                              |
| **缓存**   | 静态资源加长期哈希文件名，配合 **CDN 缓存策略**                            |

### 5.3 定期扫描

**定时让 AI 扫描项目漏洞、代码规范和冗余代码**（建议每周一次或每次大版本后）。

## 6. AI 工具分工（关键 · 模型组合决定效率）

### 6.1 推荐工具

- **博客主要用**：**Claude Code（cc）** 和 **Codex**

### 6.2 模型选择

| 优先级   | 工具组合                          | 用途       |
| -------- | --------------------------------- | ---------- |
| **首推** | **Codex + GPT-5.5**               | 全流程主力 |
| **次选** | **Claude Code + DeepSeek-V4-Pro** | 备选组合   |

### 6.3 角色分工（CRITICAL · 顶模/低模分离）

```
[顶模：负责思考 PLAN]  →  [低模：按代码规范编写实现]  →  [顶模：最后审查代码]
   ↑                                                            ↓
   └──────────────────── 反馈闭环，反复试错 ←───────────────────┘
```

- **顶模**（GPT-5.5 / DeepSeek-V4-Pro）：思考 PLAN、最终审查
- **低模**：按代码规范编写实现
- **建议分工**：**顶模思考 → 低模实现 → 顶模审查**

## 7. 博客设计（专属原则 · 区别于普通网站）

### 7.1 原则出处

- 参见文章：**《谈谈不受欢迎的博客技术特征》** —— 纸鹿摸鱼处

### 7.2 核心原则

1. **保持博客风格统一**
   - **文章页面专注阅读**（干净、留白、字体优先）
   - **相册首页专注视觉**（图片优先、动效优先）
2. **AI 绘画作品只在首页展示**
   - 因热爱 AI 绘画，故只在首页展示 AI 绘画作品
   - 其他页面专注于文章内容呈现
3. **各司其职，互不干扰**
   - 后续也会继续遵循该原则
4. **希望各位读者能喜欢本站的设计风格**
   - 也能在设计自己的博客时参考本站的设计原则

## 8. 关键红线（CRITICAL · 不要做这些事）

- ❌ **不直接搬运参考站代码到项目**（要先做原型验收）
- ❌ **不在没分析项目前就 `/init`**（会反复翻车）
- ❌ **不跳过 TDD 直接提交**（白屏测试 = 浪费时间）
- ❌ **不在多页面混用风格**（文章页 vs 相册页 vs 首页，各司其职）
- ❌ **不把原型/规范文件放在项目根**（统一放 `.trae/`）
- ✅ **必须产出 `design.md` 沉淀设计规范**
- ✅ **必须做原型图 HTML 验收（95%+ 还原度），再接入项目**
- ✅ **必须红绿测试通过再提交**
- ✅ **必须顶模最终审查代码**
- ✅ **必须遵循"文章专注阅读、相册专注视觉"原则**

## 9. 调用本 Skill 时的完整工作流（一句话总结）

```
博客有 UI 改版 / 新页面 / 样式迁移需求
  → 调起本 skill
  → 阶段 1：先说结论，AI 定整体风格
  → 阶段 2：找参考 → 写原型图 .html（产物放 .trae/prototype/）→ 验收 ≥95%
  → 阶段 3：生成 design.md（产物放 .trae/）
  → 阶段 4：（如新项目）先深度分析 → 踩坑 → /init → 生成 claude.md
  → 阶段 5：头脑风暴 → 按代码规范开发 + TDD → 顶模审查 → 提交
  → 阶段 6：动效 + 资源优化 + 定期扫描
  → 全程遵循"文章/相册/首页各司其职"博客设计原则
```
